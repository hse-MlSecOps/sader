# Backlog SADER

Основание: [архитектура](architecture.md), [контракт Worker](worker-contract.md), [инструкция по сборке](development.md), [Executor.cpp](../src/Executor.cpp), [main.cpp](../src/main.cpp), [CMakeLists.txt](../CMakeLists.txt) и [Sader/CMakeLists.txt](../Sader/CMakeLists.txt). **IMPLEMENTED:** синхронный `CALL`, владение Worker в `WorkerRegistry`, сборка с C++20 и libcurl. **TESTED:** тестовые исходники и пять зарегистрированных CTest перечислены в [development.md](development.md); результат их запуска здесь не подтверждён. **PLANNED:** все задачи ниже имеют статус `TODO`: ThreadPool, Dockerfile и GitHub Actions workflow в текущем дереве не обнаружены. **UNKNOWN:** решения, блокирующие интеграцию, перечислены в [handoff](handoff-threadpool.md#13-открытые-архитектурные-вопросы).

Приоритеты: `P0` — блокирует безопасную реализацию/проверку направления, `P1` — необходим для законченной интеграции, `P2` — улучшение после базового сценария. Владелец обозначен **ролью**, персональное назначение ещё не подтверждено: «разработчик ThreadPool» и «разработчик Docker/CI». Зависимость `—` означает отсутствие задач-предшественников в этом списке, но не отсутствие внешних требований. Критерии — условия будущей приёмки, а не сведения о выполненных проверках.
