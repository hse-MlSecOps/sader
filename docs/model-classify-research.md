# Research: classify — классификация по двум векторам и порогу

**Задача:** `feature/model-classify`
**Статус:** черновик

## Что делает функция

`classify` — **бинарная threshold-классификация по косинусной близости** (cosine similarity)
двух векторов. Это следует из контекста воркера: ModelWorker описан как
"vector normalization / cosine similarity / threshold classification", а схема аргументов
связывает `classify` с теми же двумя векторами (`vector`, `other`), что и `cosine`,
плюс дополнительный параметр `threshold`.

Алгоритм:
1. Вычисляется cosine similarity: `cos(a, b) = (a·b) / (||a|| * ||b||)`, диапазон [-1, 1].
2. Результат сравнивается с порогом: `cos(a, b) >= threshold` → `"similar"`, иначе `"dissimilar"`.

**Альтернативы, которые рассмотрены:**
- Классификация по евклидову расстоянию — отклонена: воркер про ML-эмбеддинги,
  где стандартом является cosine (см. `docs/model-normalize-research.md` и PR #19).
- Мультиклассовая классификация — отклонена: сигнатура (два вектора + один порог)
  выражает именно бинарное решение.

## Что означает порог

`threshold` — минимальное значение cosine similarity, при котором пара векторов
считается относящейся к одному классу.

- Допустимый диапазон: **[-1.0, 1.0]** — ровно диапазон cosine similarity.
  Порог вне диапазона бессмыслен (условие всегда истинно или всегда ложно) —
  это ошибка вызывающего, а не валидный вход.
- Граница включающая: `cos == threshold` → `"similar"` (стандартное `>=`,
  как в scikit-learn `predict` по `score >= threshold`).
- `NaN` запрещён: любое сравнение с NaN ложно, что молча превратило бы
  классификатор в всегда-`"dissimilar"`.
- В `execute()` аргумент `threshold` опционален (по схеме воркера); значение
  по умолчанию — **0.5** (нейтральная середина положительной близости).

## Формат возвращаемого значения

`std::string` — метка класса: `"similar"` или `"dissimilar"`.

**Альтернативы:**
- `bool` — отклонён: текущая сигнатура возвращает `std::string`, а строка
  самодокументируема в CLI-выводе воркера.
- Строка с числом (`"0.83:similar"`) — отклонена: смешивает метрику и метку;
  значение similarity доступно отдельно через `cosine()`.

## Сигнатура (решение по итогам research)

Существующая сигнатура **сохраняется** — она точно выражает алгоритм:

    std::string classify(const std::vector<double>& left,
                         const std::vector<double>& right,
                         double threshold) const;

Дополнительные параметры не нужны: метрика зафиксирована research'ем (cosine),
формат вывода — строковая метка.

Для выполнения контракта Worker (`Result` вместо исключений наружу) добавляется
override `execute(const Arguments&)`: он парсит аргументы, вызывает `classify()`
и упаковывает итог в `Result{success, output, error}`. Типизированный `classify()`
при нарушении контракта бросает `std::invalid_argument` — единый стиль с
`cosine()` (PR #19) и `normalize()` (PR #20); `execute()` исключения ловит
и превращает в `Result::fail`, поэтому наружу из воркера исключения не уходят.

## Валидация входных данных

| Случай | Поведение |
|--------|-----------|
| Пустой вектор | ошибка: нечего сравнивать |
| Разные размерности | ошибка: cosine не определён |
| Нулевой вектор | ошибка: деление на ноль в норме |
| `threshold` вне [-1, 1] | ошибка: бессмысленный порог |
| `threshold == NaN` | ошибка: сравнение неопределено |
| Нефинитные компоненты (NaN/Inf) | отсекаются на парсинге в `execute()` |

Проверки выполняются **до** вычислений — операция не запускается при нарушении контракта.
