# Технический аудит SADER: рекомендации по рефакторингу

Аудит по состоянию текущего дерева: [Worker](../include/sader/Worker.h), [реестр](../src/WorkerRegistry.cpp), [фабрика](../src/WorkerFactory.cpp), [Executor](../src/Executor.cpp), [парсер и main](../src/main.cpp), семь каталогов [workers](../workers), [CMake](../CMakeLists.txt), [подпроект](../Sader/CMakeLists.txt) и [тесты](../tests). Контекст согласования будущей параллельности: [handoff](handoff-threadpool.md). **IMPLEMENTED** — наблюдаемое поведение кода; **TESTED** — сценарий существует в исходнике теста, без заявления об успешном прогоне; **PLANNED** — рекомендация, ничего из списка не реализовано; **UNKNOWN** — требует решения/проверки. Каждая карточка имеет статус `TODO`. `P0` — существенная корректность/безопасность либо блокер безопасной многопоточности; `P1` — архитектурная/сборочная проблема; `P2` — сопровождение. Сложность `S/M/L` — ориентировочная оценка работы, не обещание сроков. Зависимости — ID этого списка, `—` означает отсутствие предшественника.

## 1. Critical — подтверждённые ошибки корректности и безопасности

### REF-001 — Исключить shell-интерпретацию аргументов процесса
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / `ProcessWorker` / L / —.
- **Место:** [workers/process/ProcessWorker.cpp:101-114](../workers/process/ProcessWorker.cpp), [116-156](../workers/process/ProcessWorker.cpp).
- **Проблема (подтверждена):** разрешённое имя команды соединяется с `args` и передаётся в `popen`, который запускает shell. Фильтр проверяет только символы `;|&` и другие из фиксированной строки, но не исключает, например, перевод строки, кавычки или подстановку специальных символов оболочки. Список разрешённых имён не делает всю строку безопасной.
- **Последствия:** аргументы могут изменить смысл команды либо вызвать дополнительные команды; при будущем параллельном запуске риск сохраняется.
- **Решение (предложение):** отказаться от shell при запуске, передавать проверенные argv напрямую через платформенный API; явно определить разрешённые аргументы и поддерживаемые ОС.
- **Критерии приёмки:** аргументы с shell-синтаксисом и переводом строки не приводят к выполнению незапрошенной команды; тесты проверяют разрешённый и запрещённый сценарий без опасных побочных действий.

### REF-002 — Корректно проверять статус завершения процесса
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / `ProcessWorker` / M / REF-001.
- **Место:** [workers/process/ProcessWorker.cpp:34-39](../workers/process/ProcessWorker.cpp), [158-166](../workers/process/ProcessWorker.cpp).
- **Проблема (подтверждена):** после `pclose` без проверки `-1` и `WIFEXITED` применяется `WEXITSTATUS(rawStatus)`; `Result.success=true` возвращается также для ненулевого exit code. `fgets`-цикл не проверяет `ferror` ([строки 45-55](../workers/process/ProcessWorker.cpp)).
- **Последствия:** ошибочный/сигнальный исход выглядит успешным; возможна некорректная интерпретация статуса и усечённого stdout.
- **Решение (предложение):** согласовать контракт `success` относительно ненулевого exit code; проверять ошибки чтения, закрытия и тип завершения до декодирования кода, выдавать определённый `Result`.
- **Критерии приёмки:** тесты покрывают код 0, ненулевой код, ошибку чтения/закрытия (через контролируемый стенд) и сигнальное завершение там, где поддержано; нет декодирования недопустимого статуса.

### REF-003 — Формировать действительный формат результата ProcessWorker
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / `ProcessWorker` / M / REF-002.
- **Место:** [workers/process/ProcessWorker.cpp:163-166](../workers/process/ProcessWorker.cpp), [81-93](../workers/process/ProcessWorker.cpp).
- **Проблема (подтверждена):** `schema().result_description` обещает JSON, но stdout вставляется в кавычки без экранирования; уже обычный `echo` с переводом строки создаёт строку, не соответствующую JSON.
- **Последствия:** парсер результата может отвергнуть ответ либо неправильно прочитать данные при кавычках/обратных слешах.
- **Решение (предложение):** определить единый формат `Result.output` и корректно сериализовать stdout (либо убрать обещание JSON после согласования контракта).
- **Критерии приёмки:** stdout с переводом строки, `"`, `\` и Unicode декодируется JSON-парсером без потерь, если выбран JSON; описание схемы соответствует результату.

### REF-004 — Ограничить сетевой доступ и размер ответа HttpWorker
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / `HttpWorker` / L / —.
- **Место:** [workers/http/HttpWorker.cpp:54-69](../workers/http/HttpWorker.cpp), [18-31](../workers/http/HttpWorker.cpp), [96-104](../workers/http/HttpWorker.cpp).
- **Проблема (подтверждена):** проверяются только префиксы `http://`/`https://`; хосты не ограничены, callback без лимита добавляет весь body в `std::string`. **Потенциальный риск** при использовании CLI с недоверенным вводом — запрос к внутреннему ресурсу и неограниченное потребление памяти.
- **Последствия:** возможны нежелательные сетевые запросы и исчерпание памяти; таймаут 10 с не ограничивает объём ответа.
- **Решение (предложение):** согласовать политику допустимых адресов/редиректов и лимит body; прерывать передачу при превышении; учитывать адрес после DNS-разрешения, если это входит в модель угроз.
- **Критерии приёмки:** тесты с локальным HTTP-сервером проверяют ограничение размера, адресов и редиректов по согласованной политике; ошибки возвращаются явно.

### REF-005 — Проверять результат операций libcurl
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `HttpWorker` / M / REF-004.
- **Место:** [workers/http/HttpWorker.cpp:96-121](../workers/http/HttpWorker.cpp).
- **Проблема (подтверждена):** возвраты всех `curl_easy_setopt` и `curl_easy_getinfo` игнорируются; после успешного `curl_easy_perform` status code может остаться `0`, если `getinfo` не удался.
- **Последствия:** диагностика и представление HTTP-статуса могут быть недостоверны.
- **Решение (предложение):** проверять `CURLcode` у операций настройки и чтения сведений; обеспечить определённый `Result` при ошибке.
- **Критерии приёмки:** обработка ошибок установки опций/чтения статуса проверена управляемыми тестами либо инъекцией зависимости; нет использования значения статуса после неуспешного `getinfo`.

## 2. Major — архитектура и технический долг

### REF-006 — Завершить `const`-контракт WorkerRegistry
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `WorkerRegistry` / S / —.
- **Место:** [include/sader/WorkerRegistry.h:14-18](../include/sader/WorkerRegistry.h), [src/WorkerRegistry.cpp:25-36](../src/WorkerRegistry.cpp).
- **Проблема (подтверждена):** объявлен `const Worker* findByName(...) const`, но определена только неконстантная перегрузка. Текущий `Executor` использует неконстантный реестр; обращение через `const WorkerRegistry` приведёт к неразрешённому символу при линковке.
- **Последствия:** обещанный интерфейс непригоден для константного клиента.
- **Решение (предложение):** определить `const`-перегрузку либо пересмотреть декларацию по согласованию публичного API; проверить оба варианта вызова.
- **Критерии приёмки:** тестовый клиент с `const WorkerRegistry&` успешно компилируется, линкуется и находит/не находит имя; текущий клиент сохраняет поведение.

### REF-007 — Согласовать реализуемость Worker и схемы
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `Worker`, `HashWorker`, `CsvWorker`, `HttpWorker`, `ModelWorker` / L / —.
- **Место:** [include/sader/Worker.h:29-42](../include/sader/Worker.h), [workers/hash/HashWorker.h:5-13](../workers/hash/HashWorker.h), [workers/csv/CsvWorker.h:5-13](../workers/csv/CsvWorker.h), [workers/http/HttpWorker.h:18-29](../workers/http/HttpWorker.h), [workers/model/ModelWorker.cpp:115-124](../workers/model/ModelWorker.cpp), [196-224](../workers/model/ModelWorker.cpp).
- **Проблема (подтверждена):** `schema()`/`execute()` по умолчанию бросают; `hash` и `csv` не переопределяют оба, `http` не переопределяет `schema()`. У `model` схема перечисляет `normalize`/`cosine`, а `execute()` принимает только `classify`.
- **Последствия:** зарегистрированные Worker доступны для discovery, но `DESCRIBE`/`CALL` частично не работают или дают противоречивое описание.
- **Решение (предложение):** решить, допустимы ли discovery-only Worker; отразить доступность в контракте/регистрации, привести `Schema` и CLI-вызовы к реальным возможностям либо реализовать недостающее по отдельному плану.
- **Критерии приёмки:** для каждого зарегистрированного Worker определён ожидаемый результат `DISCOVER`/`DESCRIBE`/`CALL`; тесты подтверждают схему и вызываемые операции.

### REF-008 — Унифицировать ошибки Executor и Worker
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `Executor`, `Worker` / M / REF-007.
- **Место:** [src/Executor.cpp:42-89](../src/Executor.cpp), [src/main.cpp:107-119](../src/main.cpp), [include/sader/Worker.h:10-14](../include/sader/Worker.h).
- **Проблема (подтверждена):** неизвестный Worker печатается в stdout, ошибка `Result` тоже в stdout, а исключение базового `schema()`/`execute()` печатается main в stderr. `Executor::execute` возвращает `void`, что усложняет программную проверку результата.
- **Последствия:** разные форматы и каналы для одной категории ошибок, осложнённая интеграция и тестирование.
- **Решение (предложение):** согласовать общую политику статуса/ошибок и границу форматирования; менять публичные сигнатуры только после решения владельца Core.
- **Критерии приёмки:** несуществующее имя, ошибка валидации и исключение дают документированный однозначный статус и проверяются тестами CLI/компонента.

### REF-009 — Уточнить парсер команд и покрыть его тестами
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `parseCommand` / M / —.
- **Место:** [src/main.cpp:16-80](../src/main.cpp), [src/main.cpp:95-112](../src/main.cpp).
- **Проблема (подтверждена):** `DISCOVER`/`DESCRIBE` берут остаток строки буквально; `CALL` делит аргументы по пробелам, перезаписывает повторные ключи и допускает пустой ключ. Кавычки не обрабатываются; отдельного теста парсера нет.
- **Последствия:** значения с пробелами недоступны из CLI, опечатки и повторы скрываются, поведение различных команд различается.
- **Решение (предложение):** сначала определить синтаксис и политику trim/пустых/повторных ключей, затем изолировать парсинг для тестов; не менять совместимость команд без решения.
- **Критерии приёмки:** таблица валидных и ошибочных команд, включая пробелы и дубликаты, закреплена автоматическими тестами и документацией CLI.

### REF-010 — Сократить ручное перечисление WorkerFactory
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `WorkerFactory` и регистрация / M / REF-007.

- **Проблема (подтверждена):** набор из семи Worker повторяется в enum, `switch` и регистрации; для нового класса нужны согласованные ручные изменения нескольких мест.
- **Последствия:** возможна рассинхронизация списка доступных/создаваемых/зарегистрированных Worker.

- **Критерии приёмки:** добавление одного Worker имеет документированную процедуру и тест, обнаруживающий пропуск регистрации или ветки фабрики.

### REF-011 — Уточнить контракт `Result` и валидацию аргументов
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `Schema`, конкретные Worker / M / REF-007, REF-008.
- **Место:** [include/sader/Worker.h:8-27](../include/sader/Worker.h), [workers/file/FileWorker.cpp:109-125](../workers/file/FileWorker.cpp), [workers/text/TextWorker.cpp:39-51](../workers/text/TextWorker.cpp), [workers/http/HttpWorker.cpp:134-147](../workers/http/HttpWorker.cpp).
- **Проблема (подтверждена):** `FileWorker` отвергает неизвестные ключи, `TextWorker` и `HttpWorker` их не проверяют; схема только описывает поля, общей проверки `required`/`type` нет; `output` — произвольная строка.
- **Последствия:** одинаковая ошибка ввода приводит к разному поведению, формат результатов не пригоден для гарантированного машинного анализа.
- **Решение (предложение):** определить правило неизвестных аргументов и ответственность за проверку Schema; описать формат результатов отдельно для каждого Worker или общий контракт без неподтверждённых обещаний.
- **Критерии приёмки:** тесты на отсутствующие/неизвестные ключи для каждой операции отражают согласованную политику; `Schema` соответствует валидации.

### REF-012 — Устранить зависимость от транзитивных include/PCH
- **Приоритет / статус / компонент / сложность / зависимости:** P2 / TODO / C++20 headers / S / —.
- **Место:** [workers/process/ProcessWorker.cpp:1-5](../workers/process/ProcessWorker.cpp), [src/main.cpp:1-7](../src/main.cpp), [src/stdafx.h](../src/stdafx.h), [Sader/CMakeLists.txt:42-44](../Sader/CMakeLists.txt).
- **Проблема (подтверждена):** `ProcessWorker.cpp` использует `WEXITSTATUS`, не подключая явно заголовок для wait-макросов; `main.cpp` использует `std::istringstream` благодаря `stdafx.h`. Некоторые заголовки напрямую зависят от косвенных include.
- **Последствия:** хрупкая переносимость и скрытые зависимости при сборке целей без PCH.
- **Решение (предложение):** подключать заголовки используемых API непосредственно в нужном translation unit, проверить сборку без PCH как дополнительную диагностику.
- **Критерии приёмки:** каждый модуль собирается с необходимыми прямыми include на поддерживаемых платформах; отсутствие PCH не ломает объявленные интерфейсы.

### REF-013 — Убрать вводящий в заблуждение вывод конструкторов

### REF-015 — Согласовать дублирование вычислений ModelWorker
- **Приоритет / статус / компонент / сложность / зависимости:** P2 / TODO / `ModelWorker` / M / REF-007.

## 4. ThreadPool readiness — подтверждённые предпосылки и потенциальные риски

ThreadPool **PLANNED**; реальные гонки в нынешнем однопоточном CLI не утверждаются. Следующие пункты блокируют **введение** конкурентного выполнения до принятия решения.

### REF-016 — Определить одновременный доступ к одному Worker
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / `Worker`, `Executor` / L / REF-007, REF-011.
- **Место:** [include/sader/Worker.h:29-44](../include/sader/Worker.h), [src/Executor.cpp:69-79](../src/Executor.cpp), [include/sader/WorkerRegistry.h:20-21](../include/sader/WorkerRegistry.h).
- **Проблема (риск при будущем ThreadPool):** `execute()` неконстантен, `WorkerRegistry` хранит по одному экземпляру на имя; контракт не гарантирует возможность одновременного `execute()` одного объекта.
- **Последствия:** потенциальная гонка данных и нарушение инвариантов нового Worker при параллельных `CALL`.
- **Решение (предложение):** до интеграции согласовать сериализацию на экземпляр либо явно проверенное разрешение параллельности и инварианты Worker; не полагаться на случайную текущую stateless-реализацию.
- **Критерии приёмки:** правило зафиксировано для всех Worker, тест на два одновременных вызова подтверждает выбранную политику, нет гонок при проверке доступным инструментом.

### REF-017 — Гарантировать жизнь захваченных Worker, Executor и CurlGlobal
- **Приоритет / статус / компонент / сложность / зависимости:** P0 / TODO / реестр, main, будущий пул / L / REF-016.
- **Место:** [src/main.cpp:82-95](../src/main.cpp), [include/sader/Executor.h:11-21](../include/sader/Executor.h), [src/WorkerRegistry.cpp:25-35](../src/WorkerRegistry.cpp), [include/sader/CurlGlobal.h:6-19](../include/sader/CurlGlobal.h).
- **Проблема (риск при будущем ThreadPool):** `Executor` хранит `WorkerRegistry&`, реестр выдаёт `Worker*`; в текущем коде срок жизни обеспечен локальным порядком создания/разрушения, но фоновая задача может пережить владельца и libcurl global state.
- **Последствия:** use-after-free, обращение к libcurl после cleanup, падение при `EXIT`.
- **Решение (предложение):** задать владельца пула и порядок stop/join до разрушения `Executor`, реестра и `CurlGlobal`; задачи должны владеть копией аргументов, а не ссылкой на локальный `Command`.
- **Критерии приёмки:** тесты остановки с ожидающими/выполняющимися задачами завершаются без dangling references; весь набор futures получает исход по согласованной политике.

### REF-018 — Определить синхронизацию реестра и вывода
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `WorkerRegistry`, `Executor` / M / REF-016, REF-017.
- **Место:** [src/WorkerRegistry.cpp:3-51](../src/WorkerRegistry.cpp), [src/Executor.cpp:23-89](../src/Executor.cpp), [src/main.cpp:95-119](../src/main.cpp).
- **Проблема (риск при будущем ThreadPool):** реестр не синхронизирует конкурентную регистрацию/поиск, а `Executor` пишет результаты напрямую в `std::cout`; при фоновых ответах возможны пересечение вывода и неопределённый порядок результатов.
- **Последствия:** потенциальная гонка при модификации реестра и нечитаемые/неатрибутируемые ответы CLI.
- **Решение (предложение):** заморозить реестр после старта либо синхронизировать чтение/запись; определить единственного владельца вывода и политику порядка ответов.
- **Критерии приёмки:** одновременная постановка и `DISCOVER`/`DESCRIBE` работают по согласованному контракту; каждый ответ принадлежит конкретной задаче и не перемешивается.

### REF-019 — Согласовать futures, исключения и семантику `CALL`
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / будущий ThreadPool, `Executor` / L / REF-008, REF-017, REF-018.
- **Место:** [include/sader/Executor.h:11-20](../include/sader/Executor.h), [src/Executor.cpp:5-20](../src/Executor.cpp), [src/main.cpp:107-119](../src/main.cpp).
- **Проблема (риск при будущем ThreadPool):** сейчас `execute`/`call` возвращают `void`, исключение ловится только в CLI-потоке; не определено, блокирует ли `CALL`, как выдаётся `std::future<Result>` и идентифицируется задание.
- **Последствия:** необработанное исключение фоновой задачи или потерянный результат; несовместимость CLI.
- **Решение (предложение):** согласовать блокирующий/асинхронный контракт, учёт заданий, обработку отказа/исключения и безопасную остановку до изменения Core; см. [handoff](handoff-threadpool.md#13-открытые-архитектурные-вопросы).
- **Критерии приёмки:** каждое принятое задание даёт результат либо явно определённую ошибку, тесты проверяют исключение, отказ после stop и CLI-формат.

## 5. CI readiness — проблемы перед автоматизацией сборки

### REF-020 — Включить все нужные тесты в CTest
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / CMake и тесты / S / —.
- **Место:** [CMakeLists.txt:19-57](../CMakeLists.txt), [Sader/CMakeLists.txt:52-151](../Sader/CMakeLists.txt).
- **Проблема (подтверждена):** `TestProcessWorker` и `TestFileWorker` создаются, но не переданы в `add_test`; CTest в подпроекте регистрирует пять других тестов.
- **Последствия:** CI с одним `ctest` не выполняет верхнеуровневый тест процесса; дубликат файлового теста усложняет сопровождение.
- **Решение (предложение):** согласовать состав тестовых целей, включить обязательные проверки через CTest и убрать ненужное дублирование после согласования с владельцем CI.
- **Критерии приёмки:** `ctest -N` показывает согласованный набор, отказ процесса/файла приводит к провалу нужного CI job.

### REF-021 — Сделать сетевые тесты детерминированными
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / `HttpWorkerTest` / M / REF-005.
- **Место:** [tests/HttpWorkerTest.cpp:5-17](../tests/HttpWorkerTest.cpp), [Sader/CMakeLists.txt:98-116](../Sader/CMakeLists.txt).
- **Проблема (подтверждена):** тест делает запрос к `https://nonexistent.invalid` и ожидает сетевую ошибку; исход зависит от DNS, прокси и окружения CI.
- **Последствия:** нестабильная проверка в Docker/CI, без покрытия успешного ответа и размера body.
- **Решение (предложение):** использовать локальный управляемый HTTP-сервер или изолированный транспортный тест; исключить внешнюю сеть из обязательного набора.
- **Критерии приёмки:** повторный прогон в offline-окружении стабилен; успех/ошибка/статус проверяются предсказуемо.

### REF-022 — Зафиксировать единую конфигурацию инструментов и тестов
- **Приоритет / статус / компонент / сложность / зависимости:** P1 / TODO / CMake, Docker/CI / M / REF-020, REF-021.
- **Место:** [CMakeLists.txt:4](../CMakeLists.txt), [Sader/CMakeLists.txt:2-12](../Sader/CMakeLists.txt), [CMakePresets.json](../CMakePresets.json), [Sader/CMakeLists.txt:35-44](../Sader/CMakeLists.txt).
- **Проблема (подтверждена):** корень объявляет минимум CMake 3.10, подпроект — 3.20; `find_package(CURL REQUIRED)` требует доступный dev-пакет libcurl; presets платформозависимы. **UNKNOWN:** результат чистой сборки Linux/CI и runtime-зависимости образа пока не зафиксированы.
- **Последствия:** автоматическая сборка может остановиться на configure/link либо запуске контейнера; неясные требования к toolchain.
- **Решение (предложение):** согласовать фактическую минимальную версию и окружение C++20/libcurl; провести чистую configure/build/CTest, затем многостадийную Docker-сборку и PR workflow по [backlog](backlog.md#b-docker-и-ci).
- **Критерии приёмки:** документированы версии toolchain/deps и команды; чистый Docker build и CI job демонстрируют configure, build и CTest без локальных артефактов.

### REF-023 — Исключить отключение assert-проверок в Release
- **Приоритет / статус / компонент / сложность / зависимости:** P2 / TODO / тестовые цели / M / REF-020.
- **Место:** [tests/test_worker_registry.cpp:20-33](../tests/test_worker_registry.cpp), [tests/testWorkerFabric.cpp:13-25](../tests/testWorkerFabric.cpp), [tests/FileWorkerTest.cpp:14-56](../tests/FileWorkerTest.cpp), [tests/test_process_worker.cpp:14-95](../tests/test_process_worker.cpp).
- **Проблема (подтверждена):** эти тесты используют `assert`, который при `NDEBUG` не проверяет условия; `testDuplicateRegistration()` в тесте реестра ([строки 7-18](../tests/test_worker_registry.cpp)) вообще не вызывается и пока содержит лишь комментарий.
- **Последствия:** Release-CTest может показать успех без выполненных проверок; дубликат регистрации не покрыт тестом.
- **Решение (предложение):** использовать проверки, активные в любой конфигурации, дополнить вызовом реального сценария дубликата.
- **Критерии приёмки:** специально нарушенное условие валит тест и в Debug, и в Release; тест дубликата действительно ожидает `std::invalid_argument`.
